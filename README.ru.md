# Local Coach

**Личный коуч-психолог-наставник с функцией body double, который учится на твоих заметках Obsidian (или других MD).**
Всё работает на твоём компьютере через локальный [Ollama](https://ollama.com): внешние API не вызываются,
заметки только читаются.

## Быстрый старт

Нужны Python 3.10+ и Ollama с двумя моделями. numpy по желанию ускоряет векторные операции
(`pip install numpy` или `apt install python3-numpy`), без него всё работает, но медленнее.

**Видеокарта** — от 8 ГБ (GTX 1070/1080, RTX 2060 Super, 3060 Ti, 4060 и выше). Обе модели вместе
занимают около 7 ГБ: `qwen3.5:9b-q4_K_M` при контексте 16 тыс. (по умолчанию) — 6,3 ГБ, `embeddinggemma` —
0,65 ГБ. На карту с 6 ГБ модель целиком не влезет: часть уйдёт на процессор, и станет заметно медленнее.
С 12 ГБ хватит и на контекст 32 тыс. Проверить: `ollama ps`, пока модель загружена, — должно быть `100% GPU`.

**Другие модели.** Коуч работает только с Ollama и требует от модели структурированный JSON-ответ (параметр `format` у Ollama, его поддерживает любая современная модель). Подойдёт любая чат-модель, которую отдаёт Ollama: `LOCAL_COACH_MODEL` (чат и быстрые вызовы), `LOCAL_COACH_HEAVY_MODEL` (извлечение, реестр, гипотезы; по желанию) и `LOCAL_COACH_EMBED_MODEL` (векторы). Проверено только на Qwen 3.5 (9B и 27B) и `embeddinggemma`, остальные модели не пробовались. Маленькие модели выдумывают чаще, но каждый факт всё равно требует дословной цитаты, которую проверяет код. Смена модели векторов пересчитывает все векторы, а пороги похожести подобраны под `embeddinggemma`. Не поддерживаются: серверы с OpenAI-совместимым API и облачные API. Так задумано: заметки не покидают твою сеть.

```bash
ollama pull qwen3.5:9b-q4_K_M
ollama pull embeddinggemma

git clone https://github.com/Jutqe/local-coach.git && cd local-coach
export LOCAL_COACH_VAULT=~/Obsidian/МойVault   # или флаг --vault
python3 coach.py plan                    # сколько работы, без вызова модели
python3 coach.py update                  # первый прогон с нуля
python3 coach.py import ~/Биография.xlsx # по желанию: таблицы, документы
python3 coach.py bio                     # твоя хронология по годам, без вызова модели
python3 coach.py calibrate               # что из старых заметок верно сейчас (вопросы)
python3 coach.py chat                    # разговор
```

Данные коуча — в `~/.local-coach` (база, память, импортированные файлы); поменять её можно
флагом `--workspace` или переменной `LOCAL_COACH_WORKSPACE`. Vault не меняется.

Прогон можно прервать в любой момент (Ctrl+C): каждый фрагмент сохраняется сразу,
повторный `update` продолжит с места остановки. Первый прогон по нескольким сотням заметок
на видеокарте занимает часы; дальше обрабатываются только новые и изменённые заметки.

## Команды

| Команда | Что делает |
|---|---|
| `update` | Обновить память: новые и изменённые заметки → факты → векторы → кластеры → обзоры → профиль → аудит → файлы. Команда по умолчанию. |
| `update --skip-synth` | Только извлечение и векторы, без синтеза. |
| `import файл…` | Добавить в память таблицу или документ: `.xlsx`, `.csv`, `.docx`, `.txt`, `.md`. Файл становится заметкой в `imports/` рабочей папки (vault не меняется) и сразу разбирается. Повторный импорт того же файла обновляет его. |
| `plan` | Посчитать фрагменты и время, ничего не меняя. |
| `status` | Состояние базы и частые ошибки (без содержимого заметок). |
| `chat` | Разговор с коучем. |
| `serve [--host H] [--port P]` | Веб-интерфейс с котом Базилием: тот же коуч в браузере, с живым ответом и режимом присутствия; работает как постоянный сервис. Подробнее — в разделе «Веб-интерфейс». |
| `bio [1988-2026] [--all]` (прежнее имя `history` работает) | Хронология по годам из базы, без модели: точно и мгновенно. Опора — строки импортированной биографии (строка таблицы = одно событие со своим периодом); из заметок и разговоров — только события и решения, не из папок проектов и идей («Проекты», «Проекты 2024», «Ideas»…), без того, что уже есть в биографии или повторяет запись того же года о том же. В конце — сколько и почему не показано, пустые годы. `--all` — всё подряд, как лежит в базе. |
| `calibrate [--limit N] [--all]` | Что из старых заметок верно сейчас: сверка с биографией, затем вопросы про оставшееся (по умолчанию до 25 за раз; `--all` — и про пропущенные). |
| `checkin` | Чек-ин: три коротких вопроса о том, что сейчас; ответы — подтверждённые факты на сегодня. |
| `reset [stage N\|depth N\|export]` | Life Reset: где ты в программе разбора накопленного и что делать дальше; `export` выгружает итоги в папку `Life Reset/` vault (чувствительное – только номером). |
| `inventory [build\|list\|plan\|reopen]` | Реестр накопленного из заметок: цели, проекты, идеи, незакрытые дела. `plan` – посчитать заранее; `reopen LR-N` – вернуть закрытое в разбор. |
| `triage [--area X] [--quick]` | Разбор реестра: решение по каждому пункту с причиной (активно, инкубатор, когда-нибудь, жду, сделано, отпустить). `--quick` – списком, «1а 2к 3о», «4?» – карточкой. В вебе (`/triage` в чате или кнопка) то же окном: один пункт на экран, пять понятных вариантов, область пункта меняется выпадающим списком, склейка одинаковых названий и кнопка «Не проект». |
| `sweep [--target N]` | Одиночные упоминания пачкой: модель выбирает самое значимое по областям, остальное ждёт твоего ответа, без него ничего не архивируется. |
| `audit` | Аудит жизни по двенадцати областям, по строке на область. |
| `hypotheses [build]` | Осторожные предположения о повторяющихся сценариях: с цитатами и другими объяснениями; статус меняешь только ты. |
| `people` | Люди из заметок: кто это, есть ли сейчас в жизни, склеить дубли; `--list` — только список. |
| `agreements` | Договорённости из разговоров: открытые и недавно закрытые; «2 с» — сделано, «2 б» — брошено, «+ текст до 2026-11-01» — добавить. |
| `eval [--n 10] [--only …]` | Оценить качество: актуальность, факты, профиль, ответы коуча — по букве на пункт. Заодно забывает неверные факты и чинит актуальность. |
| `eval --report` | Отчёт оценки: только числа по версиям и разрезам, без содержимого — можно пересылать. |
| `review` | Разобрать предложения в память из разговоров и вопросы аудита. |
| `forget текст` | Найти и забыть неверное утверждение. |
| `reextract [--path Папка/]` | Переизвлечь факты, например после правки промптов. |
| `recluster` | Пересобрать склейку фактов, например после смены порога. |
| `sanitize` | Перепроверить фильтр секретов и вычистить производные данные (модель не вызывается). |
| `name Имя` | Как называть тебя в профиле (`name` — показать, `name -` — убрать). Без имени профиль пишет «он» и не берёт имена из заметок. |
| `export` | Пересоздать файлы памяти из базы без вызова модели. |

В чате:
- `/remember текст` или фраза, начинающаяся с «запомни, что…» (или «подправь / исправь / учти, что…»;
  запоминается первая фраза), — сразу в память как подтверждённое. Сразу после этого коуч показывает
  похожее из памяти («планирует закрыть кредиты») и спрашивает, что теперь не так: номера — в прошлое,
  «н 2» — забыть. Если что-то поправил, в конце разговора коуч предложит пересобрать профиль. Относительное время («с прошлой осени») пересчитывается в дату;
- `/import путь/к/файлу.xlsx` — добавить файл, не выходя из разговора;
- `/bio [период] [--all]` — хронология по годам (как `coach.py bio`; `/history` — то же). Просьбы вроде
  «выведи всё из базы по годам», «выведи то, что у тебя есть», «покажи хронологию» идут сюда же, мимо модели:
  в разговоре коуч видит только найденное по теме (до 25 фактов), а не всю базу. Просьба о теме
  («покажи, что есть в памяти про работу») остаётся коучу — он перечисляет найденное списком, без отказов,
  а что это может быть не всё, говорит одной строкой в конце;
- `/calibrate` — вопросы о том, что из старых заметок верно сейчас;
- `/checkin` — чек-ин: как ты, что главное, что мешает;
- `/people` — люди из заметок: кто это, есть ли сейчас в жизни;
- `/agreements` — договорённости: посмотреть, отметить, добавить;
- `/review` — разобрать предложения в память. Они появляются после каждого ответа, а в
  конце сессии коуч сам спрашивает про предложения из этого разговора;
- `/forget текст`, `/sources` (откуда взята память для последнего ответа), `/new`
  (новая сессия), `/exit`.

Коуч знает, что он программа, которую ты настраиваешь: «твоя калибровка», «ты выдаёшь подсказку»
он относит к себе и отвечает, какой командой это делается, без поиска по заметкам.

Всё, что ты сказал или загрузил, сразу доступно в разговоре. Опорный профиль
пересобирается на следующем `update`.

## Прошлое и настоящее

Заметки охватывают годы, и без проверки времени профиль описывает тебя десятилетней
давности как нынешнего. Поэтому у каждого утверждения есть актуальность:

- **сейчас** — свежее упоминание (за последний год), подтверждено тобой или сверено с биографией;
- **в прошлом** — было и прошло, с периодом или годом окончания («2010–2017», «до 2019»);
- **событие** — событие или решение с датой: история по определению;
- **не проверено** — неизвестно, верно ли сейчас.

Как это выясняется, от сильного к слабому:
1. **Твои ответы.** `calibrate` спрашивает только про то, что попадает в профиль, начиная с
   важного: «с» — так и сейчас, «б 2019» — было до 2019, «и теперь …» — изменилось, «н» — неверно,
   или своими словами. Ответы хранятся по смыслу и переживают переизвлечение заметок.
2. **Сверка с хронологией.** Импортированные файлы (биография), датированные факты дневников,
   сказанное в разговорах и твои прошлые ответы — опора. Дневник — заметка с разделами по годам
   (`## 2015`, `## 2015 год`, жирная строка `**2015 - …**`, хотя бы два года) или с названием либо папкой вроде «Дневник», «Итоги по годам», «Хронология»,
   «Биография»; `update` пишет, сколько таких нашлось. Сверяются важные утверждения и всё, что
   пришло из самой хронологии (строка «работал в X, 2010–2015» сразу уходит в прошлое). Заметки из
   папок проектов и идей опорой не считаются, даже с разделами по годам.
   Модель сверяет с ними старые утверждения и ставит «в прошлом» или
   «сейчас» только со ссылкой на конкретную строку; иначе — «не проверено». Пока ты отвечаешь,
   следующие вопросы пересверяются с твоими ответами в фоне, и понятное без тебя пропускается.
3. **Правила.** Свежее года — «сейчас»; события и выполненные или брошенные цели — история.

Как это используется:
- в профиле прошлое — отдельный раздел «Прошлое», в прошедшем времени; «Сейчас в фокусе» без
  актуальной опоры уходит в «Не проверено»; давнее непроверенное помечается. Это проверяет код,
  а не просьба в промпте;
- в разговоре прошлое идёт отдельным блоком «было раньше, сейчас уже не так», у отрывков старых
  заметок указан их возраст;
- если в разговоре скажешь «я там больше не работаю», старое утверждение после `review` уйдёт в
  прошлое, а не будет забыто.

Порядок: `update` → `import` биографии → `calibrate` → `update` (или согласиться пересобрать
профиль сразу в конце `calibrate`). Новые ответы со временем стареют: «так и сейчас» старше
полутора лет снова считается непроверенным.

**Таблицы.** Каждая строка становится строкой заметки «Заголовок: значение; …»,
даты Excel распознаются. Для импортированных файлов дата загрузки не считается датой
событий: время берётся из самих строк (столбец «Год», «Дата» и т. п.).

**Плотный текст.** Модель отдаёт не больше 15 фактов за вызов (`LOCAL_COACH_MAX_FACTS`). Если
фрагмент упёрся в этот потолок — таблица, дневник, длинный список, — он делится пополам по
строкам и каждая половина разбирается отдельно (до трёх раз); делится фрагмент от 600 символов.

**Таблицы по годам.** Строка заголовков ищется среди трёх верхних (над ней может быть название
таблицы); годы в заголовках (`2015`, `2015–2017`) — полноценные подписи столбцов. Объединённая
ячейка получает весь свой диапазон: `2015–2017: …` по столбцам, `… (2015–2017)` по строкам; датой
такого факта служит начало периода, сам период остаётся в утверждении. Диапазон до последнего года таблицы
(если это нынешний или прошлый год) пишется «с 2015 по настоящее время» — это продолжение, а не
законченный период. Проверить, как таблица
разложится, до импорта: `python3 tools/import_check.py файл.xlsx` (числа) или `--show` (текст заметки
на экран). В дневнике раздел года начинает заголовок `## 2015`, жирная строка `**2015 - …**` или
строка `2015:` / `2015 год — …:`, за которой идёт список.

**Год факта.** Год, который назвала модель, принимается, только если на что-то опирается: он стоит
в тексте, заголовке или названии именно как год, это год раздела (`## 2015`) или — у заметки с надёжной
датой (в шапке или имени файла) — год заметки ±1 («в прошлом году», «вчера»). Иначе факт получает дату
раздела, надёжную дату заметки или остаётся без даты. Так дата переноса заметок (mtime) не выдаёт
старое за свежее, а число не становится годом: «2000 оборотов», «стоил 1990 руб», «1500–2000»,
«2000-е» — не годы, и строка «**2000–3000 об:**» раздел не датирует. Такие даты из прошлых
извлечений `update` снимает сам.

**Проекты и идеи.** Заметки из папок «Проекты», «Projects», «Идеи», «Ideas» (и с добавкой к имени:
«Проекты 2024») — проектные: в разговоре коуч о них знает, но в хронологию (`bio`) и в опору
сверки актуальности они не идут — годы там обычно планы и характеристики, а не события жизни.

## Что получится

```
~/.local-coach/
  coach.sqlite3              вся память и прогресс
  imports/                   импортированные файлы в виде заметок
  STATUS.md                  счётчики
  memory/profile.md          опорный профиль (его коуч держит в каждом разговоре)
  memory/profile_plain.md    тот же профиль для чтения: только содержание, без источников, дат и пометок
  memory/domains/*.md        обзоры областей жизни
  memory/hypotheses.md       гипотезы о паттернах — только как гипотезы
  memory/projects_and_ideas.md  идеи и проекты отдельно от целей жизни
  memory/clusters_review.md  проверка склейки фактов (для настройки порога)
```

У каждого пункта есть источники вида `путь/заметки.md#L10-L42` и пометки:
«одно упоминание», «заметок: N», «подтверждено тобой», «смягчено аудитом»,
«возможно устарело».

## Как устроено

1. **Чтение vault.** Разбирается frontmatter, теги и `[[ссылки]]`. Дата заметки берётся
   из шапки (`date:`, `created:`), из имени файла (`2024-05-14.md`, «Дневник 2015»), иначе из mtime.
   mtime помечается как ненадёжная дата; если у большинства заметок он одинаковый (это дата
   копирования), дата считается неизвестной. Заметка режется на фрагменты около 7000
   символов **по заголовкам**; разделы с датой в заголовке (`## 2024-05-20`, `## 2015`, строка `**2015 — …**`) получают
   свою дату, разделы разных лет в один фрагмент не склеиваются.
2. **Синхронизация.** Неизменённые фрагменты переиспользуются по хэшу: правка одного
   раздела заметки не заставляет переизвлекать её целиком.
3. **Извлечение.** Модель возвращает факты строго по JSON-схеме: тип, область, о ком
   (сам/другой человек), статус намерения, дата, дословная цитата. Код проверяет цитату по
   тексту; невыдуманная цитата = опора. Общие знания из статей отбрасываются.
4. **Векторы** (embeddinggemma с её префиксами задач) для фактов, фрагментов и итогов сессий.
5. **Склейка.** Похожие факты одной области собираются в кластер (порог 0.90 по замеру:
   перефразировки 0.93+, «брат/сестра живёт в Москве» 0.88). У кластера считается число
   независимых заметок, даты и самая свежая формулировка — так видно, что устойчиво, а что
   единично, и как менялось со временем.
6. **Актуальность** (см. «Прошлое и настоящее»): отметки, сверка с хронологией, правила.
7. **Синтез.** По каждой области модель получает лучшие кластеры с короткими id (`C12`) и
   ссылается только на них; код проверяет ссылки и не даёт поднять статус цели выше, чем в
   исходных фактах («хочет» не станет «делает»). Из обзоров собирается профиль.
8. **Аудит** проверяет каждый пункт профиля по дословным цитатам. Неподтверждённое убирается,
   преувеличенное смягчается, важное и неясное уходит тебе вопросом в `review`.
9. **Чат.** Гибридный поиск (векторы + полнотекстовый trigram-индекс, объединение через RRF)
   по фактам, фрагментам и прошлым сессиям. Ответ идёт потоком. После ответа в фоне
   выделяются предложения в память, они ждут твоего решения в `/review`. В конце сессии
   сохраняются итог и договорённости, и следующая сессия начинается с них.
10. **Твои решения главнее.** «Подтвердил» и «забыть» хранятся отдельно от фактов и
   применяются к похожим фактам и после переизвлечения заметок.

Кэш синтеза привязан к входным данным: при обновлении пересчитываются только области,
где что-то изменилось.

## Договорённости

В конце сессии модель записывает **новые** шаги, которые ты сам решил сделать (со сроком,
если он звучал: «до пятницы» пересчитывается в дату), и отмечает, что стало с открытыми
договорённостями, о которых говорили: сделано, брошено, продвинулось. Почти повторяющиеся
договорённости отсекаются кодом.

Коуч видит открытые договорённости и в начале разговора, если срок подошёл или прошла
неделя, коротко спрашивает об одной — без отчёта. История выполненного и брошенного идёт ему
как материал для наблюдений о паттернах. При первом запуске договорённости из итогов прежних
сессий переносятся в таблицу один раз.

## Чек-ин: что сейчас

`coach.py checkin` или `/checkin` в чате — три коротких вопроса: как ты (цифра 1–10 и пара
слов), что сейчас главное, что мешает. Ответы сразу становятся подтверждёнными фактами с
сегодняшней датой — то есть «сейчас»; последний чек-ин (до двух недель) коуч видит в
разговоре дословно, как самое свежее о тебе. Самочувствие по последним чек-инам показывается
рядом («5 → 6 → 7»). Если чек-ина не было больше трёх дней, чат напомнит при старте.

## Люди

На обновлении (этап 6/8) модель находит людей в фактах — по имени («Персона») или по роли
(«мама», «начальник») — в именительном падеже; имя, которого нет в тексте утверждения,
отбрасывается кодом. Код собирает упоминания и годы. `coach.py people` (или `/people`)
спрашивает про часто упоминаемых: кто это, есть ли сейчас в твоей жизни, не тот ли это человек,
что уже есть под другим именем («= Персона» — склеить). Ответы хранятся по имени и переживают
повторное извлечение. В разговоре коуч видит людей, о которых речь: названных в твоей реплике и
связанных с найденными воспоминаниями. Список — `coach.py people --list` и `memory/people.md`.

## Режим присутствия (body double)

Садишься за дело и хочешь, чтобы кто-то просто был рядом: в чате `/focus глава книги` или
словами — «побудь рядом, сажусь за отчёт». Коуч отвечает «Начали» и дальше **сам, без твоих
сообщений**, раз в 1–2 минуты пишет короткую реплику («Я здесь.», «Работаем.»), а каждые
10 минут — сколько прошло. Реплики готовятся одним вызовом модели при включении, под задачу;
реплики, будто коуч видит твою работу («прогресс виден»), отсеиваются.

Пока ты набираешь текст, коуч молчит, строку ввода не ломает. Если напишешь что-то — ответит
одной короткой фразой, без вопросов и советов. Выключить: `/focus`, «стоп», «закончил»,
«готово» — коуч скажет, сколько ты проработал; это сохраняется (`focus_sessions`) и попадает
в итог сессии. Частота — `LOCAL_COACH_FOCUS_EVERY` (по умолчанию не реже раза в 120 с).

По желанию – направление и план: `/focus LR-12 на 50 минут черновик` (или «на час», «2ч»). Время
сессии записывается к пункту Life Reset, и `reset` показывает, сколько за 30 дней ушло на каждое
активное направление. С планом коуч сам закрывает сессию, когда время вышло, а в конце спрашивает
«как прошло?»: первый ответ одной фразой записывается к сессии. В вебе всё это – окно «Побудь рядом»
и кольцо прогресса у таймера.

## Веб-интерфейс (кот Базилий)

`python3 coach.py serve` — тот же коуч в браузере (по умолчанию `http://127.0.0.1:3012/`). Лицо коуча — кот Базилий:
пока ты ждёшь, он думает, при ответе кивает и «говорит», в режиме присутствия дремлет рядом, а когда возвращаешься
после долгого перерыва — потягивается. Ответ идёт потоком, как в терминале.

- **Доступ.** В сеть (`--host 0.0.0.0`) — только с PIN-кодом. `LOCAL_COACH_WEB_PIN` — временный: при первом входе страница
  просит задать свой PIN (от 4 символов), он хранится хэшем (`.web_pin` в рабочей папке), временный перестаёт действовать;
  позже его меняют в ⚙. Без PIN сервер слушает только localhost. Вход ставит подписанную куку на 30 дней, после 5 неверных PIN вход блокируется на 10 минут.
  Тексты разговоров в журнал не пишутся. Адрес и порт — `LOCAL_COACH_WEB_HOST`, `LOCAL_COACH_WEB_PORT`.
- **Что есть.** Разговор, `/think`, режим присутствия (кнопка «Побудь рядом» или слова), `/bio`, `/sources`, `/new`.
  То, что спрашивает построчно (`/review`, `/calibrate`, `/checkin`, `/people`, `/agreements`, `/import`, `/forget`,
  `/remember`), остаётся в терминале.
- **Постоянная работа.** Сессия одна. Через 90 минут тишины итог сохраняется сам; при остановке сервиса — тоже.
  Если Ollama на ПК выключился, коуч сам переходит на запасной (если задан), включился — возвращается.
  Режим присутствия без открытой страницы выключается через 10 минут.
- **Фоновые звуки.** Микшер для концентрации: шум (белый, розовый, коричневый, с тембром), водопад, ручей, шелест листьев,
  ветер, дождь, дождь по лужам и мурчание. У каждого слоя своё включение и громкость, слои накладываются; шум можно
  включать вместе с «Побудь рядом». Шум и часть слоёв страница рисует сама. Чтобы взять живую запись, положи файл
  `<слой>.wav` (или `.mp3`, `.ogg`) в `localcoach/web/audio/` (имена слоёв: `stream`, `leaves`, `puddles` и другие),
  код менять не нужно. Записей в репозитории нет: выбери те, чья лицензия тебя устраивает.
- **Ласка.** Кнопки «погладить», «почесать ушко» и «обнять»: кот реагирует, мурчит или мяукает (звуки отключаются).
  Коучу это ничего не меняет.
- **Внешний вид.** В настройках (⚙ у кота): версия кота (1 «мультяшный», 2 «мудрый»), очки, масть, светлая или тёмная
  тема. Выбор хранится в браузере.
- **Как поставить сервисом.** Юнит systemd вида `ExecStart=python3 /путь/к/coach.py serve --host 0.0.0.0 --port 3012`,
  `Restart=always`, `EnvironmentFile` с PIN-кодом и `TimeoutStopSec=600` (при остановке сохраняется итог сессии).

## Оценка качества

`coach.py eval` показывает небольшую случайную выборку из четырёх частей, на каждый пункт —
одна буква:

| Часть | Вопрос | Ответы |
|---|---|---|
| Актуальность | верно ли «сейчас / в прошлом»? | в — верно, н — неверно (сразу спросит, как правильно) |
| Факты | верно ли модель поняла заметку? | в, и — искажено, ч — не про меня, н — неверно (забудет) |
| Профиль | верно ли это о тебе сейчас? | в, ч — частично, у — устарело, н — неверно |
| Ответы коуча | как тебе ответ из прошлых разговоров? | х — хорошо, о — нормально, м — мимо, ф — ошибка в фактах, п — прошлое как настоящее |

Enter — пропустить, 0 — следующая часть, 00 — закончить. Уже оценённое не повторяется.
В базе остаются только вердикты и хэши пунктов, поэтому `eval --report` — это числа: доля
верного с 95%-интервалом по каждой версии кода и модели, разрезы по источнику актуальности и
разделу профиля. Так видно, стало ли лучше после обновления; на выборке из 10 интервал широкий,
поэтому полезно оценивать понемногу, но регулярно.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Сквозные тесты на заглушке Ollama (`tests/fake_ollama.py`): все команды на маленьком
выдуманном vault — обновление, импорт, актуальность, вопросы, чат и договорённости, режим присутствия, чек-ин и люди, оценка,
служебные команды, миграция старой базы, даты (дневник по годам, плотный фрагмент, дата
изменения файла). Модель и сеть не нужны, прогон — около секунды.
Качество модели они не проверяют (для этого `eval`), а проверяют, что код правильно разбирает
ответы и отбрасывает неподтверждённое: выдуманные цитаты, ссылки на несуществующие кластеры,
вердикты без опоры, дубли договорённостей, секреты.

## Как настроить коуча

Коуч **не дообучается**: веса модели не меняются, и ничего из сказанного ему модель не переобучает. Его поведение складывается из четырёх вещей, и все их можно менять:

- **Память.** Скажи в чате: `/remember ...` (или «запомни, что ...»), «поправь, что ...» меняет запомненный факт, `/forget ...` убирает его. `/review`, `/calibrate`, `/checkin` и `/people` дают подтвердить или поправить то, что он понял из заметок. То, что он помнит, влияет на ответы.
- **Глубина и рассуждение.** `/depth 1|2|3` (практическая, аналитическая, глубокая рефлексия) и `/think` (рассуждение включено или выключено на разговор).
- **Инструкции.** Все инструкции модели лежат в репозитории простым текстом: `localcoach/prompts.py` (русские) и `localcoach/prompts_en.py` (английские). Характер коуча – `COACH_SYSTEM`; извлечение фактов, профиль, реестр и остальные задачи имеют свои промпты. Правь их, перезапускай коуча, а после правки промпта извлечения запусти `python3 coach.py reextract`. В промптах же лежат и правила безопасности (без диагнозов, без выдуманных фактов, осторожные гипотезы), поэтому при правке сохраняй их. Менять инструкции прямо из чата пока нельзя: возможная будущая функция.
- **Модели и язык.** `LOCAL_COACH_MODEL`, `LOCAL_COACH_HEAVY_MODEL`, `LOCAL_COACH_EMBED_MODEL`, `LOCAL_COACH_LANG` (и переключатель языка в веб-настройках). Подойдёт любая модель, которую Ollama отдаёт со структурированным ответом (см. «Другие модели» выше).

## Настройки (переменные окружения)

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `LOCAL_COACH_VAULT` | — | путь к vault (вместо флага `--vault`) |
| `LOCAL_COACH_WORKSPACE` | `~/.local-coach` | база и файлы памяти |
| `LOCAL_COACH_OLLAMA` | `http://localhost:11434` | адрес Ollama |
| `LOCAL_COACH_OLLAMA_PORTS` | `11434-11439` | если Ollama не ответил на своём порту, коуч ищет его на этих портах того же адреса и запоминает найденный; пусто — не искать |
| `LOCAL_COACH_MODEL` | `qwen3.5:9b-q4_K_M` | модель |
| `LOCAL_COACH_EMBED_MODEL` | `embeddinggemma:latest` | эмбеддинги |
| `LOCAL_COACH_HEAVY_MODEL` | — (как модель) | отдельная модель покрупнее для тяжёлых вычислений: извлечение фактов, названия и отбор пунктов реестра, гипотезы, люди; чат и быстрые вызовы остаются на основной. Флаг `--heavy-model`. Если модели нет в Ollama, команда говорит об этом и идёт на основную. Кэши не хранят имя модели: уже извлечённое остаётся от прежней, пока не пересчитать (`reextract`) |
| `LOCAL_COACH_SYNTH_MODEL` | — (как модель) | модель покрупнее для обзоров, профиля, аудита и сверки с биографией: там нужно рассуждать, а вызовов немного. Флаг `--synth-model`. Смена модели пересчитывает синтез и сверку |
| `LOCAL_COACH_NAME` | — | имя для профиля (вместо `coach.py name`) |
| `LOCAL_COACH_LANG` | `en` | язык интерфейса, промптов для модели и памяти: `en` (по умолчанию) или `ru`; для русского: `LOCAL_COACH_LANG=ru` (английский: веб-страница, команды, сообщения, промпты, ввод ответов и даты). Выбирается при запуске; одна рабочая папка – один язык: после смены языка запусти `python3 coach.py reextract`, чтобы память пересобралась на новом |
| `LOCAL_COACH_FOCUS_EVERY` | `120` | режим присутствия: реплика не реже, чем раз в столько секунд (и не чаще, чем вдвое чаще) |
| `LOCAL_COACH_NUM_CTX` | `16384` | контекст, один на все вызовы (смена num_ctx перезагружает модель) |
| `LOCAL_COACH_CHUNK_CHARS` | `7000` | размер фрагмента |
| `LOCAL_COACH_CLUSTER_THRESHOLD` | `0.90` | порог склейки фактов; после смены — `recluster` |
| `LOCAL_COACH_MIN_SIMILARITY` | `0.38` | слабее этого векторные совпадения в разговор не идут |
| `LOCAL_COACH_THINK_EXTRACT` / `_SYNTH` / `_CHAT` | `0` | `1` — включить режим рассуждения (в разы медленнее) |
| `LOCAL_COACH_CHAT_TIMING` | `0` | `1` — печатать время каждого ответа в чате (сравнить с рассуждением и без) |
| `LOCAL_COACH_CHAT_BUDGET` | `26000` | бюджет контекста чата в символах |
| `LOCAL_COACH_OLLAMA_FALLBACK` | — | запасной Ollama, если основной недоступен (например, модель обычно на ПК с видеокартой, а коуч на сервере): `chat`, `checkin`, `review`, `forget` переходят на него, с меньшим контекстом и без рассуждения. Флаг `--ollama-fallback` |
| `LOCAL_COACH_FALLBACK_CHAT_BUDGET` | `18000` | бюджет контекста чата на запасном Ollama |

С `LOCAL_COACH_THINK_CHAT=1` чат показывает «(думаю…)» и точки по ходу рассуждения; если рассуждение
съело весь лимит и ответа нет, коуч сразу отвечает без него. На 9B-модели рассуждение в чате — это
минута и больше на ответ.

## Регулярное обновление

Ollama может работать на другом компьютере в домашней сети (например, на ПК с видеокартой),
а коуч — на сервере. Пример ночного обновления из cron (если Ollama недоступен, скрипт
просто выйдет с ошибкой подключения):

```
30 3 * * * cd ~/local-coach && LOCAL_COACH_VAULT=~/Obsidian/МойVault python3 coach.py update >> ~/.local-coach/update.log 2>&1
```

Чат и `update` можно запускать одновременно: два `update` сразу не запустятся.

## Приватность

- Заметки не изменяются. Заметки, похожие на хранилище паролей или содержащие токен, ключ
  или номер карты, целиком не отправляются модели.
- Запросы идут только на указанный Ollama. Если он на другом компьютере, трафик идёт по HTTP
  внутри домашней сети; можно указать Tailscale-адрес. Адрес вне домашней сети (не localhost, не
  192.168/10/172.16, не Tailscale 100.64/10) отклоняется, перенаправления не выполняются.
- Облачные модели Ollama (`…:cloud`, `…-cloud` или с `remote_host` в `/api/show`) отклоняются
  для всех ролей: с ними заметки ушли бы на ollama.com. Имя модели — только точное (или с
  `:latest`), без подбора «похожей».
- Не открывай порт 11434 в интернет.

## Ограничения

- 9B-модель ошибается: путает области, обобщает из одного случая, иногда вставляет в ответ
  лишнее из памяти. Код ловит то, что можно проверить (цитаты, ссылки, статусы), остальное
  исправляется через `review` и `/forget`.
- Порог склейки откалиброван на нейтральных примерах. Посмотри `clusters_review.md`
  после первого прогона.
- Это инструмент для рефлексии, а не психотерапия и не медицинская помощь.
